# 持仓复盘输出模板

本文定义 `/holding-review` 页面使用的结构化复盘输出模板。目标不是生成自由散文，而是输出可直接渲染、可落库、可历史回放的固定结构。

## 1. 适用范围

用于以下复盘类型：

- `general`
- `weekly`
- `monthly`
- `quarterly`

AI 角色固定为：`交易专家`

输入上下文来自当前系统真实数据，包括：

- 当前持仓摘要
- 历史成交与最近三笔关键动作
- 原始进场决策
- 最近二次分析记录
- 最近买卖决策记录
- 财报与公司画像
- 技术面、情绪、新闻与市场背景

---

## 2. 顶层输出字段

必须输出以下字段：

- `performance_summary`
- `execution_summary`
- `risk_summary`
- `discipline_summary`
- `next_action_summary`
- `conclusion_tag`
- `tabs`

### 2.1 字段定义

#### `performance_summary`
用于总结这段持仓最终结果如何。

应回答：

- 最终收益是否符合预期
- 收益质量如何
- 是逻辑兑现还是运气主导

#### `execution_summary`
用于总结执行质量如何。

应回答：

- 买入、加减仓、观察、卖出节奏是否合理
- 是否有追高、犹豫、拖延、机械执行等问题

#### `risk_summary`
用于总结风险是否上升或缓解。

应回答：

- 风险暴露变化
- 逻辑证伪信号是否出现
- 仓位是否开始不匹配

#### `discipline_summary`
用于总结方法与纪律层面的亮点或问题。

应回答：

- 哪些规则帮忙避免了错误
- 哪些规则本来写了但没有执行
- 哪些经验值得保留，哪些习惯需要修正

#### `next_action_summary`
用于给出后续动作建议。

应回答：

- 下一步更适合继续观察、准备减仓还是准备卖出
- 下一个重点观察条件是什么
- 应优先管理什么风险

#### `conclusion_tag`
只允许以下枚举值：

- `logic_ok`
- `need_recheck`
- `execution_issue`
- `risk_rising`
- `prepare_reduce`
- `prepare_sell`

标签含义：

- `logic_ok`：原逻辑仍成立，当前以继续跟踪和执行计划为主
- `need_recheck`：核心假设需要重新核查，暂不应机械沿用旧结论
- `execution_issue`：主要问题出在执行过程，而非全部来自逻辑错误
- `risk_rising`：风险正在上升，需要提高警惕和跟踪频率
- `prepare_reduce`：更偏向准备减仓，而不是继续放任持有
- `prepare_sell`：更偏向准备退出或显著降低仓位

---

## 3. 固定 Tabs 模板

`tabs` 必须固定为 4 个对象，顺序固定，不能增删，不能换序。

### Tab 1：执行与卖出复盘

```json
{
  "id": "execution_review",
  "title": "执行与卖出复盘",
  "summary": "一句顶部结论",
  "evidence": ["理由1", "理由2"]
}
```

重点覆盖：

- 买入后是否严格按计划执行
- 卖出规则是否提前定义、是否真正参考
- 是否出现追高、犹豫、拖延、机械补仓等问题

### Tab 2：结果复盘

```json
{
  "id": "result_review",
  "title": "结果复盘",
  "summary": "一句顶部结论",
  "evidence": ["理由1", "理由2"]
}
```

重点覆盖：

- 最终收益率、浮盈浮亏演变
- 收益来自逻辑兑现还是运气
- 亏损来自逻辑错误还是执行错误

### Tab 3：方法与纪律

```json
{
  "id": "discipline_review",
  "title": "方法与纪律",
  "summary": "一句顶部结论",
  "evidence": ["理由1", "理由2"]
}
```

重点覆盖：

- 哪条规则帮忙避免了大错
- 哪条规则写了却没执行
- 下次要保留什么、改掉什么

### Tab 4：后续动作

```json
{
  "id": "next_action",
  "title": "后续动作",
  "summary": "一句顶部结论",
  "evidence": ["理由1", "理由2"]
}
```

重点覆盖：

- 综合前 3 个 Tabs 后，下一步更适合做什么
- 应重点观察什么触发条件
- 如何体现 `conclusion_tag`

要求：

- 不能只复述前文
- 必须明确下一阶段最关键动作
- 必须说明为什么现在要这样处理

---

## 4. 写作规则

1. 每个 Tab 先写 `summary`，再写 `evidence`
2. `summary` 只写 1 个顶部结论，不要展开成长段落
3. `evidence` 至少给出 1 条理由，建议 2~4 条
4. 必须同时看到“结果”和“过程”
5. 不能只复述盈亏数字
6. 必须能沉淀为下次还可复用的纪律
7. 不要输出 markdown 代码块，不要输出额外解释文本
8. 必须返回结构化对象，不要返回半结构化 JSON 片段

---

## 5. 推荐语义映射

结合 `/mnt/github/stock/股票买卖模版.md` 的复盘语义，建议这样映射：

- `执行与卖出复盘` ← 第四阶段 4.1 卖出规则 + 4.2 止盈计划
- `结果复盘` ← 第四阶段 4.3 卖后结果复盘
- `方法与纪律` ← 第四阶段 4.4 方法复盘
- `后续动作` ← 综合前 3 部分后给出下一阶段建议

---

## 6. 示例结构

```json
{
  "performance_summary": "收益结果尚可，但没有明显跑赢预期。",
  "execution_summary": "执行节奏总体合格，但高位兑现不够果断。",
  "risk_summary": "短期波动加大后，仓位暴露开始偏高。",
  "discipline_summary": "主要问题不是选错标的，而是止盈纪律执行偏弱。",
  "next_action_summary": "继续观察冲高后的承接强度，若放量滞涨则准备减仓。",
  "conclusion_tag": "prepare_reduce",
  "tabs": [
    {
      "id": "execution_review",
      "title": "执行与卖出复盘",
      "summary": "执行主线基本正确，但卖出预案使用不够主动。",
      "evidence": [
        "买入后没有出现情绪化追高加仓。",
        "进入高波动阶段后，仍偏依赖被动等待而非主动管理仓位。"
      ]
    },
    {
      "id": "result_review",
      "title": "结果复盘",
      "summary": "这次持仓结果为正，但超额收益不强。",
      "evidence": [
        "当前仍保持浮盈，说明原始逻辑并未完全失效。",
        "收益表现没有显著拉开与同类资产的差距。"
      ]
    },
    {
      "id": "discipline_review",
      "title": "方法与纪律",
      "summary": "真正需要修正的是止盈纪律，而不是买入逻辑本身。",
      "evidence": [
        "规则中已经写了高估阶段要分批兑现，但执行不够坚决。",
        "这次经验应保留前期分笔建仓，改掉高位阶段反应偏慢。"
      ]
    },
    {
      "id": "next_action",
      "title": "后续动作",
      "summary": "若后续冲高乏力或放量滞涨，应优先准备减仓。",
      "evidence": [
        "风险暴露已经开始上升，继续被动持有的性价比下降。",
        "当前更需要主动管理仓位，而不是单纯等待回撤后再判断。"
      ]
    }
  ]
}
```
